# Java Annotation 
Java Annotations are special markers in Java that provide metadata (information about the code) to the compiler, tools, or runtime environment. They do not directly change program logic, but they influence how code is compiled, analyzed, or executed.

### They start with the @ symbol.

Example:
```java
@Override
public String toString() {
    return "Example";
}
```
Here @Override tells the compiler that the method overrides a superclass method.

## Why Annotations Are Used

Annotations help to:  
Give instructions to the compiler  
Generate code automatically  
Perform runtime processing    
Improve readability and maintainability

Example uses:  
Frameworks like Spring Framework use annotations for dependency injection.  
Hibernate uses annotations for ORM mapping.  
JUnit uses annotations for writing test cases.

## Built-in Java Annotations

Java provides several predefined annotations.

### @Override

Indicates a method overrides a superclass method.
```java
class Animal {
    void sound() {}
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Bark");
    }
}
```

✔ Helps compiler detect mistakes.

### @Deprecated

Marks a method or class as old and not recommended.
```java
@Deprecated
void oldMethod() {}
```
Compiler shows a warning if it is used.

### @SuppressWarnings

Suppresses compiler warnings.
```java
@SuppressWarnings("unchecked")
List list = new ArrayList();
```

### @FunctionalInterface

Used for interfaces with exactly one abstract method (Lambda support).
```java
@FunctionalInterface
interface MyInterface {
    void show();
}
```
### Types of Annotations
1. Marker Annotation

Example:
```java
@Override
```
2. Single Value Annotation
```java
@SuppressWarnings("unchecked")
```
3. Full Annotation
```java
@Author(name="Rahul", date="2025")
```
4. Creating Custom Annotation

You can create your own annotation.

Example:
```java
@interface MyAnnotation {
    String value();
}
```
Usage:
```java
@MyAnnotation(value="Hello")
class Test {
}
```
5. Meta-Annotations

Meta-annotations define how annotations behave.

Common ones:

Annotation	Purpose
@Target	Where annotation can be applied
@Retention	How long annotation is retained
@Inherited	Allows subclass inheritance
@Documented	Included in Javadoc

Example:
```java
import java.lang.annotation.*;

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)

@interface MyAnnotation {
    String value();
}
```
6. Retention Policies
Policy	Meaning
SOURCE	Removed after compilation
CLASS	Stored in class file
RUNTIME	Available at runtime via reflection
7. Example with Reflection
```java
@Retention(RetentionPolicy.RUNTIME)

@interface Info {
    String author();
}

@Info(author="Rahul")
class Test {}

public class Main {
    public static void main(String[] args) {
        Info info = Test.class.getAnnotation(Info.class);
        System.out.println(info.author());
    }
}
```
Output:
```
Rahul
```


# Custom Annotations in Java

Custom annotations are annotations that you create yourself to add metadata to classes, methods, fields, or parameters. They are commonly used in frameworks and tools to process information at compile-time or runtime.

## Creating a Custom Annotation

A custom annotation is defined using the @interface keyword.

Example
```java
@interface MyAnnotation {
    String value();
}
```
Here:
```java
@interface defines an annotation.

value()// is called an annotation element.
```
2. Using the Custom Annotation
```java
@MyAnnotation(value = "Hello World")
class Test {
}
```
If the element name is value, you can omit the name:
```java
@MyAnnotation("Hello World")
class Test {
}
```
3. Adding Meta-Annotations

Meta-annotations define how your annotation behaves.
```java
// Example
import java.lang.annotation.*;

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)

@interface MyAnnotation {
    String value();
}
```


## Explanation
| Meta Annotation | Meaning                             |
| --------------- | ----------------------------------- |
| `@Target`       | Where the annotation can be applied |
| `@Retention`    | How long the annotation exists      |
| `@Inherited`    | Allows inheritance to subclasses    |
| `@Documented`   | Included in Javadoc                 |



## Target Types

ElementType specifies where annotation can be used.

Examples:
```java
@Target(ElementType.TYPE)      // class, interface
@Target(ElementType.METHOD)    // method
@Target(ElementType.FIELD)     // variables
@Target(ElementType.PARAMETER) // parameters
@Target(ElementType.CONSTRUCTOR)

// Example:

@Target(ElementType.TYPE)

@interface Author {
    String name();
}

// Usage:

@Author(name="Rahul")
class Book {
}

```
## Retention Policies


| Policy    | Description                             |
| --------- | --------------------------------------- |
| `SOURCE`  | Removed after compilation               |
| `CLASS`   | Stored in `.class` file                 |
| `RUNTIME` | Available during runtime via reflection |




Example:
```java
@Retention(RetentionPolicy.RUNTIME)
```
## Accessing Custom Annotation Using Reflection
```java
import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)

    String author();
}

@Info(author="Rahul")

// Rahul
```

# What Reflection Means

Reflection lets a program examine or manipulate classes, methods, fields, and constructors during runtime, even if they were not directly referenced in the code.

Normally:  
Code structure is fixed at compile time.

With reflection:  
Code structure can be discovered and used dynamically at runtime.


## Reflection API in Java

In Java, the Reflection API is part of the java.lang.reflect package.

It allows you to:  
Get information about classes  
Access methods and fields  
Create objects dynamically  
Call methods dynamically  
Modify private variables
```java
// Example (Java)
import java.lang.reflect.Method;

class Test {
    public void display() {
        System.out.println("Hello Reflection");
    }
}

public class Demo {
    public static void main(String[] args) throws Exception {
        Class<?> cls = Class.forName("Test");

        Object obj = cls.getDeclaredConstructor().newInstance();

        Method m = cls.getMethod("display");

        m.invoke(obj);
    }
}
```
### What happens here

**Class.forName()** loads the class at runtime.

**newInstance()** creates the object dynamically.

**getMethod()** finds the method.

**invoke()** executes the method.

### Common Uses of Reflection

Reflection is heavily used in frameworks such as:  
Spring Framework   
Hibernate ORM   
JUnit

## Typical use cases:

Dependency Injection  
ORM mapping  
Serialization/Deserialization   
Testing frameworks  
Dynamic class loading

## Advantages

✔ Dynamic behavior  
✔ Useful for frameworks and libraries  
✔ Can access private members  

## Disadvantages

❌ Slower performance  
❌ Breaks encapsulation  
❌ Harder to debug  
❌ Security restrictions may apply  

Accessing methods, fields, and constructors dynamically means using reflection to inspect and manipulate a class during runtime instead of directly calling them in code. In Java, this is done using the java.lang.reflect package.

Below are the three main things you can access dynamically with the Reflection API.

## Accessing Constructors Dynamically

A constructor can be obtained and used to create objects at runtime.
```java
// Example
import java.lang.reflect.Constructor;

class Student {
    String name;

    public Student(String name) {
        this.name = name;
    }
}

public class Test {
    public static void main(String[] args) throws Exception {

        Class<?> cls = Class.forName("Student");

        Constructor<?> constructor = cls.getConstructor(String.class);

        Object obj = constructor.newInstance("Rahul");

        System.out.println(obj);
    }
}
// Steps
// Load the class using Class.forName()
// Get constructor using getConstructor()
// Create object using newInstance()
```
## Accessing Methods Dynamically

Reflection can call methods during runtime even if the method name is determined later.
```java
// Example
import java.lang.reflect.Method;

class Demo {
    public void show() {
        System.out.println("Hello Reflection");
    }
}

public class Test {
    public static void main(String[] args) throws Exception {

        Class<?> cls = Class.forName("Demo");

        Object obj = cls.getDeclaredConstructor().newInstance();

        Method method = cls.getMethod("show");

        method.invoke(obj);
    }
}
// Steps
// Get method using getMethod()

// Call method using invoke()
```

## Accessing Fields Dynamically

Fields (variables) can also be accessed or modified at runtime.
```java
// Example
import java.lang.reflect.Field;

class Person {
    public String name = "John";
}

public class Test {
    public static void main(String[] args) throws Exception {

        Class<?> cls = Class.forName("Person");

        Object obj = cls.getDeclaredConstructor().newInstance();

        Field field = cls.getField("name");

        System.out.println(field.get(obj));

        field.set(obj, "Rahul");

        System.out.println(field.get(obj));
    }
}
// Output
// John
// Rahul
```


## Important Reflection Classes

| Class         | Purpose                   |
| ------------- | ------------------------- |
| `Class`       | Represents class metadata |
| `Constructor` | Represents constructors   |
| `Method`      | Represents methods        |
| `Field`       | Represents variables      |


## Key Methods Used

| Method                | Purpose                   |
| --------------------- | ------------------------- |
| `getConstructor()`    | Get constructor           |
| `getMethod()`         | Get public method         |
| `getDeclaredMethod()` | Get private/public method |
| `getField()`          | Get public field          |
| `getDeclaredField()`  | Get private field         |
| `invoke()`            | Call method               |
| `set()`               | Modify field value        |



# Garbage Collection in Java

When a program creates objects, they occupy memory in the **Heap**.  
If those objects are no longer referenced, they become **garbage**.

The **Garbage Collector** automatically detects and deletes such objects.

---

## Definition

**Garbage Collection** is the automatic process of reclaiming memory by destroying objects that are no longer in use.

---

## Example

```java
public class Test {
    public static void main(String[] args) {

        Test obj1 = new Test();
        Test obj2 = new Test();

        obj1 = null;   // object becomes eligible for GC
    }
}
```

## How Garbage Collection Works

Steps:  
- Objects are created in the Heap Memory.  
- The JVM tracks object references.  
- When an object has no references, it becomes eligible for GC.  
- The Garbage Collector removes it and frees memory.  




## Unreachable Objects (Easy Explanation)

An object becomes unreachable when no variable is pointing to it anymore.
In other words, there is no reference to access that object in the program.

When an object becomes unreachable, it becomes eligible for Garbage Collection (GC).
```java
// Example
Integer i = new Integer(4); 
// the Integer object is reachable through reference 'i'

i = null; 
// the Integer object is no longer reachable
```
## Step-by-Step Explanation

```java
Object Creation
Integer i = new Integer(4);
```
A new object with value 4 is created in Heap Memory.

The variable i stores the reference (address) of that object.

So the object is reachable because i is pointing to it.
```output
i  ----->  Integer object (4)
```
```java
// Removing the Reference

i = null;
```
The variable i no longer points to the object.

Now no variable refers to that Integer object.
```output
i  ----->  null
Integer object (4)  ❌ no reference
```

Object Becomes Unreachable

Since no reference exists, the object cannot be accessed anymore.

This object becomes eligible for Garbage Collection.

The Garbage Collector may remove it from memory to free space





## Requesting Garbage Collection

Once an object becomes **eligible for Garbage Collection**, it may **not be destroyed immediately**.  
The **Garbage Collector runs at the JVM's discretion**, and its execution time **cannot be predicted**.

However, we can **request the JVM to run the Garbage Collector**.

There are two ways to do this:

---

### 1. Using `System.gc()`

This **static method** requests the JVM to perform garbage collection.

```java
System.gc();
```
### 2. Using Runtime.getRuntime().gc()

This method also requests garbage collection through the Runtime class.
```java
Runtime.getRuntime().gc()
```


# Java Memory Model (JMM)
The Java Memory Model describes how Java threads see and access shared variables and how changes made by one thread become visible to other threads.

It is essential for multithreading and concurrency.

## Main Components of Java Memory Model

The JMM mainly consists of two memory areas:

### 1. Main Memory

- Shared among all threads  
- Stores:
    - instance variables  
    - static variables  
    - objects

All threads read and write shared variables from main memory.

### 2. Working Memory (Thread Memory)

- Each thread has its own working memory  
- It contains copies of variables from main memory

A thread:
- Loads variables from main memory  
- Works on them in working memory  
- Writes updated values back to main memory  

### Basic Workflow

1. Variable stored in main memory  
2. Thread copies it to working memory    
3. Thread modifies it locally  
4. Updated value written back to main memory

```java
// Example
class Counter {
    int count = 0;
}

public class Demo {
    public static void main(String[] args) {
        Counter c = new Counter();

        Thread t1 = new Thread(() -> c.count++);
        Thread t2 = new Thread(() -> c.count++);
    }
}
```
Here:  
- count is stored in main memory  
- Each thread may work on its own copy  
- Without synchronization, results may be inconsistent.  


## Key Problems Solved by JMM


### 1. Visibility

Ensures that changes made by one thread are visible to others.

Example solution:

volatile keyword
### 2. Atomicity

Ensures operations are completed fully without interruption.

Example solution:

synchronized block
### 3. Ordering

Ensures instructions execute in the correct order.

## Important Keywords Related to JMM
### 1. volatile

Ensures visibility of shared variables.

volatile int count;
### 2. synchronized

Ensures mutual exclusion and memory visibility.
```java
synchronized void increment() {
    count++;
}
```
### 3. final

Ensures safe initialization of variables.

# Stack vs Heap Memory

| Feature           | Stack Memory                               | Heap Memory                           |
| ----------------- | ------------------------------------------ | ------------------------------------- |
| Purpose           | Stores method calls and local variables    | Stores objects and instance variables |
| Memory allocation | Automatic                                  | Dynamic                               |
| Access speed      | Faster                                     | Slower compared to stack              |
| Memory management | Managed automatically when method finishes | Managed by Garbage Collector          |
| Visibility        | Thread-specific                            | Shared between threads                |
| Size              | Smaller                                    | Larger                                |




### 1. Stack Memory

Stack memory is used to store:

Local variables

Method calls

Reference variables

Each thread in Java has its own stack.
```java
// Example
public class Test {
    public static void main(String[] args) {
        int a = 10;
        int b = 20;
    }
}
```
Explanation:  
`a` and `b` are stored in stack memory.

### 2. Heap Memory

Heap memory is used to store:

Objects

Instance variables

Objects created using `new` are stored in the heap.
```java
// Example
class Student {
    int id;
}

public class Test {
    public static void main(String[] args) {
        Student s = new Student();
    }
}
```
Explanation:  
Object `new Student()` is stored in heap memory.  
Reference `s` is stored in stack memory.



## Key Differences
**Stack**  
✔ Stores method execution data  
✔ LIFO structure (Last In First Out)  
✔ Automatically cleared after method ends  

**Heap**
✔ Stores objects and instance variables  
✔ Managed by Garbage Collection  
✔ Objects live until no references exist  
```java
// Simple Example Showing Both
class Demo {
    int x = 5;
}

public class Test {
    public static void main(String[] args) {
        Demo d = new Demo();
    }
}

// Memory usage: 
// Stack: reference `d`  
// Heap: object `Demo`  
```
