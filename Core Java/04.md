# What is Multithreading?

Multithreading is a feature of Java that allows concurrent execution of two or more threads. A thread is a lightweight subprocess, the smallest unit of execution in a program.

## Benefits of multithreading:

Improved performance on multi-core processors.

Better resource utilization (while one thread waits, another can run).

Responsive programs (e.g., GUI apps or servers handling multiple requests).

## Creating Threads in Java

Java provides two main ways to create threads:

### Method 1: Extending Thread Class
```java
// key points: 

// Worker + Job together → the thread itself knows what task to do.  (thred ko pata hota hai usse kay karna hai)
// You create a class that is a thread, and inside it you define run() — the task.  
// Limitation: since the class already is a thread, it cannot extend another class.  (chuki ye ek thread name ke class ko exten kar raha to ye dusra koi aur class nahi extend kar sakta hai)

class MyThread extends Thread {
    public void run() { // entry point for the thread
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
}

// or

class MyThread extends Thread {
    public void method1() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + " method1: " + i);
        }
    }

    public void method2() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + " method2: " + i);
        }
    }

    public void run() {  // jvm hamesa run ko call karta hai to run function ko hona jaruri hai 
        method1();
        method2();
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();

        t1.start(); // start the thread
        t2.start();
    }
}
```
>Notes:  
>Overriding run() defines the code to execute.  
>start() actually starts the new thread (calls run() internally).

### Method 2: Implementing Runnable Interface
```java
key point:
// Worker and Job are separate → Runnable is just the job; Thread is the worker.  (ishme hmm worker ko job assign karte hai)
// You can use the same job for multiple threads. 
// Your class can still extend another class because you’re not extending Thread.(it extends the another calss)

class MyRunnable implements Runnable {
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Thread t1 = new Thread(new MyRunnable());
        Thread t2 = new Thread(new MyRunnable());

        t1.start();
        t2.start();


        // or 

        MyRunnable job = new MyRunnable(); // job

        Thread t1 = new Thread(job); // worker 1
        Thread t2 = new Thread(job); // worker 2

        t1.start();                  // worker 1 does the job
        t2.start();                  // worker 2 does the same job
    }
}
```

# Thread Lifecycle – “Life of a Thread as a Journey”

Think of a thread like a person on a journey. A thread moves through states just like a person goes through stages of preparation, travel, waiting, and completion.

## States of a Thread

| State                                 | Meaning                                 | Analogy                                 |
| ------------------------------------- | --------------------------------------- | --------------------------------------- |
| **New / Created**                     | Thread object created but not started   | You bought a ticket but haven’t boarded |
| **Runnable / Ready**                  | Thread is ready to run, waiting for CPU | Standing at the gate, ready to board    |
| **Running**                           | Thread is executing                     | Actively traveling on the train         |
| **Waiting / Blocked / Timed Waiting** | Waiting for resource or signal          | Waiting at a red signal or station      |
| **Terminated / Dead**                 | Thread finished execution               | Reached destination                     |

>Memory Tip: Think New → Runnable → Running → Waiting → Terminated like “Born → Ready → Active → Paused → Done”.




# Synchronization – “Only One Person Can Use the Room”

When multiple threads share the same resource (like a bank account or printer), race conditions can occur.
Synchronization ensures only one thread accesses the resource at a time.

## Code Example: Synchronization

```java
class Bank {
    private int balance = 1000;

    // synchronized ensures one thread at a time
    public synchronized void withdraw(int amount) {
        if (balance >= amount) {
            System.out.println(Thread.currentThread().getName() + " is withdrawing " + amount);
            balance -= amount;
            System.out.println("Remaining balance: " + balance);
        } else {
            System.out.println("Insufficient balance for " + Thread.currentThread().getName());
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Bank bank = new Bank();

        Runnable task = () -> {
            bank.withdraw(700);
        };

        Thread t1 = new Thread(task, "Thread 1");
        Thread t2 = new Thread(task, "Thread 2");

        t1.start();
        t2.start();
    }
}
```




# Thread Pool
Thread Pools – “A Team of Workers Waiting for Tasks”

Creating threads repeatedly is expensive.
ThreadPool = a group of ready-to-go threads that execute tasks efficiently.

### Code Example: Thread Pool
```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

public class ThreadPoolDemo {
    public static void main(String[] args) {
        ExecutorService pool = Executors.newFixedThreadPool(3); // 3 threads

        for (int i = 1; i <= 5; i++) {
            int taskNo = i;
            pool.submit(() -> {
                System.out.println("Executing Task " + taskNo + " by " + Thread.currentThread().getName());
            });
        }

        pool.shutdown(); // stop accepting new tasks
    }
}
```
## Note

**Each iteration does this:   
create task → send to thread pool  
But tasks are NOT directly assigned to threads immediately.  
They go into a Task Queue inside the thread pool**

>Memory Tip: Think of ThreadPool as a team of chefs in a kitchen. You assign orders (tasks) to any available chef (thread). No chef sits idle for long.


# Deadlock
Deadlocks – “Two People Blocking Each Other Forever”

Deadlock occurs when two or more threads wait forever for resources held by each other.

## Simple Example
```java
class Resource {
    String name;
    Resource(String name) { this.name = name; }
}

public class DeadlockDemo {
    public static void main(String[] args) {
        Resource r1 = new Resource("R1");
        Resource r2 = new Resource("R2");

        Thread t1 = new Thread(() -> {
            synchronized (r1) {
                System.out.println("Thread 1 locked R1");
                try { Thread.sleep(100); } catch(Exception e) {}
                synchronized (r2) {
                    System.out.println("Thread 1 locked R2");
                }
            }
        });

        Thread t2 = new Thread(() -> {
            synchronized (r2) {
                System.out.println("Thread 2 locked R2");
                try { Thread.sleep(100); } catch(Exception e) {}
                synchronized (r1) {
                    System.out.println("Thread 2 locked R1");
                }
            }
        });

        t1.start();
        t2.start();
    }
}
```
Memory Tip: Deadlock = “Two people facing each other, each holding a pencil the other needs forever.”

## ✅ How to Avoid Deadlock:

Lock resources in the same order  
Use timed locks (tryLock)    
Minimize synchronized blocks

### Quick Memory Tricks for Long-Term Recall  
**Thread Lifecycle:** “Born → Ready → Active → Paused → Done”  
**Synchronization:** Only one thread = key to the bathroom  
**Thread Pool:** Team of workers handling tasks  
Deadlock: Two people blocking each other forever  
**Priority:** Think Thread.sleep(), wait(), notify(), join() as “pauses and signals”

# File Handling in Java 📂☕
File handling in Java allows a program to create, read, write, and delete files stored on the system. Java mainly uses classes from the java.io and java.nio.file packages for this purpose.



## Creating a File 🆕

Java uses the File class to create and manage files.
```java
import java.io.File;
import java.io.IOException;

public class CreateFileExample {
    public static void main(String[] args) {
        try {
            File myFile = new File("example.txt");
            if (myFile.createNewFile()) { // createNewFile() tries to physically create the file.
                System.out.println("File created: " + myFile.getName());
            } else {
                System.out.println("File already exists.");
            }
        } catch (IOException e) {
            System.out.println("An error occurred.");
            e.printStackTrace();
        }
    }
}
```

## Reading a File 📖

Use Scanner or BufferedReader to read file content.
```java
import java.io.File;
import java.util.Scanner;

public class ReadFileExample {
    public static void main(String[] args) {
        try {
            File myFile = new File("example.txt");
            Scanner reader = new Scanner(myFile);

            while (reader.hasNextLine()) { 
                // hasNextLine() checks if another line exists in the file. The loop continues until the end of the file.
                String data = reader.nextLine();
                System.out.println(data);
            }

            reader.close();
        } catch (Exception e) {
            System.out.println("Error reading file.");
            e.printStackTrace(); // it preint detailed error
        }
    }
}
```

# BufferedReader
BufferedReader is a class in Java used to read text from a character input stream efficiently. It reads large chunks of data into a buffer, making reading faster than reading character by character.

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public class BufferedReaderExample {
    public static void main(String[] args) {
        try {
            BufferedReader br = new BufferedReader(new FileReader("example.txt"));
            String line;

            while ((line = br.readLine()) != null) {
                // readLine():
                // Reads one line from the file
                // Returns:
                // the line (String) if data exists
                // null when the file ends  
                // The loop continues until the end of the file.
                System.out.println(line);
            }

            br.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}


// stop at line 
public class ReadPartialFile {
    public static void main(String[] args) {
        try (BufferedReader br = new BufferedReader(new FileReader("example.txt"))) {
            String line;
            int count = 0;
            int maxLines = 3; // stop after 3 lines

            while ((line = br.readLine()) != null && count < maxLines) {
                System.out.println(line);
                count++;
            }

        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
// stop at perticular work
while ((line = br.readLine()) != null) {
    if (line.contains("word")) {
        break; // stop reading
    }
    System.out.println(line);
}

// stop at perticular character
int charLimit = 50;
int charCount = 0;

while ((line = br.readLine()) != null) {
    if (charCount + line.length() > charLimit) {
        break; // stop before exceeding the limit
    }
    System.out.println(line);
    charCount += line.length();
}
```
>**Explanation**:  
>FileReader opens the file.  
>BufferedReader reads it efficiently.  
>readLine() reads one line at a time.

# Java Serialization

Serialization in Java is the process of converting an object into a byte stream so that it can be stored in a file, sent over a network, or saved in memory.

Later, this byte stream can be converted back into the original object using Deserialization.

## Simple Definition

**Serialization** → Object → Byte Stream

**Deserialization** → Byte Stream → Object

### Why Serialization is Used

Serialization is useful for:  
Saving objects in a file  
Sending objects through a network  
Storing objects in databases  
Session management in web applications

## Serializable Interface

To serialize an object, the class must implement the Serializable interface from java.io.
```java
import java.io.Serializable;

class Student implements Serializable {
    int id;
    String name;
}
```

Serializable is a marker interface.

It does not contain any methods.

### ObjectOutputStream (Serialization)

Used to write objects to a file.

Example
```java
import java.io.*;

class Student implements Serializable {
    int id;
    String name;

    Student(int id, String name){
        this.id = id;
        this.name = name;
    }
}

public class Main {
    public static void main(String[] args) {
        try {

            Student s1 = new Student(101, "Rahul");

            FileOutputStream fos = new FileOutputStream("student.ser");
            ObjectOutputStream oos = new ObjectOutputStream(fos);

            oos.writeObject(s1);

            oos.close();
            fos.close();

            System.out.println("Object Serialized");

        } catch(Exception e){
            System.out.println(e);
        }
    }
}
```
This program stores the object in a file called student.ser.

### ObjectInputStream (Deserialization)

Used to read objects from a file.

Example
```java
import java.io.*;

public class Main {
    public static void main(String[] args) {

        try {

            FileInputStream fis = new FileInputStream("student.ser");
            ObjectInputStream ois = new ObjectInputStream(fis);

            Student s = (Student) ois.readObject();

            System.out.println(s.id + " " + s.name);

            ois.close();
            fis.close();

        } catch(Exception e){
            System.out.println(e);
        }
    }
}
// Output:  
// 101 Rahul
```
## `transient` Keyword

If you do not want a variable to be serialized, use transient.

Example:
```java
class Student implements Serializable {
    int id;
    String name;
    transient String password;
}
```
password will not be saved in the serialized file.

## serialVersionUID

It is a unique ID used during deserialization to verify that sender and receiver classes are compatible.

Example:
```java
class Student implements Serializable {
    private static final long serialVersionUID = 1L;
}
```
